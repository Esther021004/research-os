Why I built Research OS

연구는 여러 개인데,
기록은 여기저기에 흩어져 있었어요.

석사 과정을 보내면서 개인 연구와 여러 프로젝트, 미팅을 함께 진행하다 보니 주제마다 해야 할 일을 관리하는 데 어려움을 느꼈습니다. 자료를 찾다가 발견한 논문도 “나중에 읽어야지” 하고 넘기기 쉬웠고요.

필요했던 것은 단순히 할 일을 적는 목록만은 아니었습니다. 각 연구가 무엇을 위한 것인지, 지금 어느 단계인지, 어떤 논문을 어디까지 읽었는지, 미팅에서 무엇을 결정했는지를 한곳에서 이어 보고 싶었습니다.

“그래서 지금, 어떤 연구의 무엇을 해야 하지?”
이 질문에 답할 수 있는 나만의 연구 공간을 만들었습니다.

그래서 프로젝트를 중심으로 논문·미팅·할 일을 연결하고, AI는 논문의 구조를 파악하고 저장된 기록을 살펴보는 보조 도구로 넣었습니다. 처음부터 완벽한 계획을 세우기보다, 일단 기록하고 나중에 구체화할 수 있도록 설계했습니다.

02 /

논문 한 편을, 끝까지 연결해서

“나중에 읽어야지” 했던 논문을 다시 찾고, 구조를 파악하고, 읽은 내용을 내 기록으로 남깁니다.

STEP 01

찾고 모으기

제목·DOI로 외부 검색하거나 링크·PDF를 직접 등록합니다. 서지정보와 중복 여부를 확인합니다.

STEP 02

구조 파악하기

원문 기반 AI 분석으로 프레임워크와 목차를 확인합니다. 근거 페이지·문장을 검토하고 구조를 수정합니다.

STEP 03

읽고 기록하기

목차에서 PDF 페이지로 이동합니다. 읽은 섹션을 체크하고 메모·하이라이트·재검토 표시를 남깁니다.

STEP 04

다시 활용하기

태그와 컬렉션, 메모 검색으로 자료를 찾습니다. BibTeX·논문 목록·읽기 메모를 내보내 글쓰기에 활용합니다.

외부 검색은 Crossref에 등록된 자료를 대상으로 하며, 검색 결과 확인과 PDF 업로드·원문 분석은 별도 단계입니다. AI 분석은 연결 설정이 필요하며 결과는 원문과 함께 검토해야 합니다.
PAPERS /

논문을 저장하는 것에서,
이해하고 다시 활용하는 것까지

논문 관련 기능은 ‘라이브러리 → 구조 분석 → 원문 읽기 → 기록 재활용’이라는 하나의 흐름으로 구성했습니다.

01 · Collect

발견한 논문을 놓치지 않기

대시보드에서 제목·링크를 바로 저장하거나 PDF를 업로드합니다. Research Agent에서는 논문 제목이나 DOI로 외부 검색창을 열 수 있습니다.

  • Crossref 검색 결과에서 제목·저자·연도·DOI를 확인한 뒤 선택하여 등록
  • DOI를 통한 서지정보 조회와 직접 수정
  • 이미 저장한 DOI·제목은 기존 항목을 안내하여 중복 방지
  • 프로젝트가 정해지지 않은 논문은 기타·미분류로 보관

검색 결과가 곧 원문은 아닙니다. PDF 자동 다운로드나 모든 논문 검색을 보장하지 않으며, 원문 분석은 별도로 진행합니다.

02 · Understand

프레임워크와 목차로 구조 파악하기

PDF 또는 본문을 준비한 뒤 분석 버튼을 누르면 AI가 논문의 구조를 정리합니다. 막연한 요약을 읽는 대신 연구가 어떤 논리로 이어지는지 살펴봅니다.

  • 입력·방법·결과 등 논문 내용에 따른 프레임워크 모식도
  • 원문에서 파악한 목차와 페이지 정보
  • 모식도 노드에서 근거 페이지·문장 확인
  • 원문과 인용문 일치 여부 표시, 근거가 없으면 재검토

AI가 추출한 결과는 틀리거나 누락될 수 있습니다. 제목·링크만으로 원문 전체를 분석하지 않으며, 스캔 PDF에는 별도 OCR이 필요할 수 있습니다.

03 · Correct

AI 결과를 내 읽기 방식에 맞게 고치기

분석 결과를 정답으로 고정하지 않습니다. 프레임워크와 목차를 직접 수정하고, 분석 없이 목차를 입력해서 읽기 관리를 시작할 수도 있습니다.

  • 모식도 노드와 목차 항목 편집
  • 섹션 제목·페이지 등 읽기에 필요한 정보 보완
  • 새 분석 적용 전 검토, 보관된 이전 구조 복원
  • ‘방법론만 검토’처럼 논문을 읽는 목적 기록
04 · Read

목차에서 원문으로, 읽던 곳에서 다시

목차의 섹션을 누르면 연결된 PDF 페이지로 이동합니다. 마지막 읽던 페이지와 섹션별 완료 상태를 남겨 다음 읽기를 이어갑니다.

  • 읽을 논문·읽는 중·완독 상태 관리
  • 목차별 읽음 체크와 체크된 섹션 기준 진행률
  • 중요하거나 어려운 섹션에 다시 볼 표시
  • PDF 페이지 번호 기준 이동 — 인쇄된 쪽수와 다를 수 있음

진행률은 실제 읽은 시간이나 자동 시선 추적이 아니라 사용자가 체크한 목차를 기준으로 합니다.

05 · Annotate

해석과 질문을 원문 위치에 남기기

문장을 선택해 하이라이트와 메모를 저장하거나, 페이지 전체에 질문·해석·기억할 점을 기록합니다.

  • 선택 문장과 메모를 해당 PDF 페이지에 연결
  • 메모를 눌러 원문 페이지로 돌아가기
  • 페이지 텍스트 선택이 어려운 경우에도 페이지 메모 활용
  • 제목뿐 아니라 작성한 메모에서도 검색
06 · Reuse

쌓인 기록을 다음 연구에 활용하기

태그·컬렉션과 검색으로 필요한 논문을 다시 찾고, 읽기 기록을 글쓰기나 정리에 활용합니다.

  • 태그·컬렉션·프로젝트·읽기 상태로 자료 정리
  • BibTeX, 논문 목록, 읽기 메모 내보내기
  • 불필요한 논문은 확인 후 라이브러리에서 삭제
  • 읽은 기록은 대시보드의 논문 잔디와 연결

현재 논문 삭제는 목록·읽기 기록 삭제입니다. 업로드한 PDF 파일은 로컬에 보존됩니다.

AI는 선택 기능입니다. 논문 등록·수동 목차 편집·원문 읽기·메모·검색·읽기 기록에는 AI 연결이 필수는 아닙니다. 자동 분석은 별도 연결이 필요하며 추출된 원문을 AI 제공자에게 전송합니다. 외부 검색은 검색어를 Crossref로 전달합니다.
Claude 구독 연결도 지원합니다. 최신 소스와 Mac 앱 0.2.0에서 Claude Code에 본인 계정으로 로그인한 뒤, AI 연결 설정 → Claude 구독 · 로컬 연결 → Claude 연결 확인을 선택하세요. 논문 분석과 Research Agent에 Sonnet을 사용합니다. 구독 한도를 함께 사용하며 계정의 추가 사용량 요금 설정은 별도로 확인해야 합니다. API로 자동 전환하지 않습니다. 실제 Pro 계정 호출은 사용자 환경에서 확인이 필요합니다.

기록 흐름을 설명하기 위한 대화 예시

기록은 가볍게, 확정은 명확하게.

채팅에 남긴 명확한 기록 요청은 미정 항목으로 담고, 모호한 입력은 저장 여부를 먼저 확인합니다. 날짜가 없는 일정은 임의의 날짜에 넣지 않습니다.

  • “실험 결과 정리해야 해”
    할 일 후보를 먼저 기록
  • “지난 미팅에서 뭘 결정했지?”
    자료 전송 동의 후 저장된 기록을 참고해 AI 답변
  • “GLES 논문 찾아줘”
    외부 검색창에서 검색어 확인 → 후보 선택 → 등록

미정 기록 분류는 보수적인 문구 규칙을 사용합니다. 모든 입력을 AI가 완벽하게 이해하는 기능은 아니며, 한 줄에 하나씩 입력하는 방식이 적합합니다.

Python을 직접 설치하지 않고 앱 아이콘으로 실행하는 방식입니다. 현재 Intel(x86_64) 빌드이며 개발자의 Mac에서 주요 기능을 확인했습니다.

  1. 앱 ZIP 압축 해제
  2. Research OS.app을 응용 프로그램 폴더로 이동
  3. 앱 실행 후 첫 프로젝트 만들기

다른 Mac·Apple Silicon 미검증, Apple 공증 없음. 보안 경고가 나타날 수 있습니다. 포함 라이브러리·시각 자산의 배포 조건 확인이 남아 있어 공개 배포 최종본은 아닙니다.

Mac 앱 · 릴리스 상태 확인 ↗
다운로드 버튼은 GitHub Releases 목록으로 연결됩니다. 해당 ZIP이 게시되어 있을 때만 받을 수 있습니다. 파일이 없다면 아직 공개되지 않은 상태입니다. Mac 앱은 공개 배포 조건 확인 전에는 제공하지 않습니다. GitHub 저장소 방문 ↗

처음에는 빈 연구 공간입니다

  1. 첫 프로젝트를 만들고 이름·설명·색상을 정합니다.
  2. 논문을 등록하고 읽기 목적·목차·메모를 남깁니다.
  3. 할 일에 마감일을 넣어 캘린더에서 확인합니다.
  4. 미팅록을 프로젝트에 연결합니다.
  5. 필요할 때 AI를 연결해 분석·질문 기능을 사용합니다.

배포 파일에는 개발자의 개인 기록·업로드 PDF·로그인 정보·예시 데이터 파일을 넣지 않았습니다. 같은 컴퓨터에서 이미 사용했다면 저장된 자신의 기록이 다시 표시될 수 있습니다.

저장과 개인정보

소스 버전: 논문·PDF·인증 정보는 실행 폴더의 data-release, 프로젝트·미팅·일정·할 일 등은 현재 브라우저 저장소에 보관합니다.

앱 버전: 사용자 컴퓨터의 Application Support 아래 Research OS 전용 영역에 데이터를 보관합니다. 앱과 소스 사이에 기록이 자동으로 동기화되지는 않습니다.

브라우저 데이터를 삭제하거나 기기를 바꾸기 전에 중요한 기록을 백업하세요. 사용한 폴더 전체를 다시 공유하면 개인 자료·인증 정보가 포함될 수 있습니다.

지원 범위와 비용: 기본 관리는 각자 로컬에서 실행합니다. AI는 각자 지원되는 연결 방식을 설정하며 제공자별 이용 한도·요금이 적용될 수 있습니다. 다중 사용자 협업·클라우드 동기화·외부 캘린더 동기화·자동 음성 전사·스캔 PDF OCR은 제공하지 않습니다. 프로젝트 Workflow 생성은 규칙 기반, 논문 자동 분석은 AI 기반입니다.
